# Lab 1 — Requirements Engineering & UML Use-Case Modelling

**Problem Statement #58: Digital Art Commission & Watermarking Portal**

An art commission platform where clients submit visual creative briefs, artists submit watermarked WIP progress drafts, and final high-res source files unlock upon milestone payment.

**Actors:** Client Buyer, Digital Artist, Payment Gateway (external system)

## Deliverables

| File | Description |
|---|---|
| `requirements.docx` | Requirements table — 5 Functional Requirements (FR-001–FR-005) and 2 Non-Functional Requirements (NFR-001–NFR-002), each with ID, Type, Description, Priority, Acceptance Criteria, and Rationale |
| `usecase_diagram.pdf` | UML use-case diagram — all actors and use cases, with `«include»` (Upload WIP Draft → Apply Watermark; Download Final Asset → Generate Signed Download URL) and `«extend»` (Request Revision → Review Draft) relationships |
| `usecase_flow_spec.docx` | One-page use-case flow for "Make Milestone Payment & Unlock Final Asset" — preconditions, postconditions, main success scenario, and one alternate flow (payment declined) |
